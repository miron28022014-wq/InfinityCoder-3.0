# Security Policy

## Reporting a vulnerability

Please do not publish exploitable vulnerabilities, credentials, access tokens, private project files, or personal data in a public issue.

Until a dedicated private security contact is published, contact the repository owner through GitHub's private contact options if available. If no private contact option is available, open a minimal issue asking for a secure reporting channel without including exploit details.

Include:
- affected version/commit and operating system;
- impact and prerequisites;
- minimal reproduction steps;
- possible mitigation, if known.

Do not test against systems or data you do not own or have permission to test.

## User safety

- Treat AI-generated shell commands and file changes as untrusted until reviewed.
- Never commit API keys, tokens, passwords, private keys, model credentials, or personal data.
- Keep dependencies and packaged runtimes updated.
