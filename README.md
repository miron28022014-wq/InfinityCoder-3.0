# InfinityCoder 3.0

**Автономная AI-среда разработки для Windows с инструментами работы с проектом и локальной памятью.**

InfinityCoder — настольное приложение на Tauri, React и TypeScript. Оно объединяет редактор кода, файловый проводник и AI-инструменты в одном интерфейсе. AI-модель и провайдер должны быть настроены пользователем; наличие приложения само по себе не означает, что модель уже загружена или работает без настройки.

> **Статус:** Windows-сборка прошла CI: проверка TypeScript, сборка frontend, сборка NSIS-установщика, проверка наличия установщика и загрузка артефакта. Это подтверждает успешность сборки, но не заменяет полноценное ручное тестирование на разных компьютерах.

## Скачать

- **Последняя опубликованная версия:** [GitHub Releases](https://github.com/miron28022014-wq/InfinityCoder-3.0/releases)
- **Сборки CI:** [Actions → Build InfinityCoder (Windows installer)](https://github.com/miron28022014-wq/InfinityCoder-3.0/actions/workflows/build-windows.yml)

Когда релиз опубликован, скачайте файл `InfinityCoder_*_x64-setup.exe) в разделе Assets. Если доступен только артефакт Actions, откройте успешный запуск workflow и скачайте `InfinityCoder-Windows-Installer` — это ZIP с установщиком. Артефакты Actions временные и могут истечь; для обычного распространения используйте Releases.

## Установка Windows

1. Скачайте установщик из Assets релиза или распакуйте ZIP артефакта CI.
2. Запустите `InfinityCoder_*_x64-setup.exe`.
3. Следуйте инструкциям установщика.
4. Откройте InfinityCoder и настройте AI-провайдера/модель в приложении.

Установщик собирается для Windows x64. В текущей сборке workflow включает Vulkan-вариант `llama-server`; доступность ускорения зависит от оборудования, драйверов и совместимости runtime. Модельные файлы могут потребовать отдельной загрузки и не обязательно входят в установщик.

Если Windows показывает предупреждение SmartScreen, не обходите его автоматически: сначала убедитесь, что файл получен из официального репозитория проекта и соответствует опубликованным контрольным суммам, если они предоставлены.

## Возможности проекта

По текущей документации и исходникам проект включает:

- редактор кода с подсветкой синтаксиса и вкладками;
- файловый проводник и операции с файлами проекта;
- AI-инструменты для чтения, создания и изменения файлов и запуска команд;
- поиск по файлам и проектной памяти;
- сохранение состояния редактора и историю действий в интерфейсе;
- роли агентов и режим координации нескольких работников;
- интеграцию с Git-инструментами и веб-инструментами;
- настройки модели/провайдера и интерфейса.

Фактическая доступность конкретных возможностей зависит от конфигурации, выбранной модели и состояния интеграций. Не считайте список гарантией отсутствия ошибок во всех сценариях.

## Конфиденциальность и безопасность

- Не вставляйте секреты, пароли, токены или приватные ключи в промпты и файлы, которые могут отправляться внешнему AI-провайдеру.
- При использовании удалённого провайдера отправляемые ему запросы и контекст обрабатываются согласно его условиям. Локальный интерфейс не означает автоматически, что весь AI-процесс работает офлайн.
- Проверяйте команды и изменения, предложенные агентом, прежде чем выполнять их в важных проектах.
- Делайте резервные копии проекта и используйте Git.
- Не запускайте установщик из непроверенных зеркал.

## Для разработчиков

### Требования

- Node.js 22.x и npm;
- Rust stable и Cargo;
- инструменты сборки Windows для Tauri/NSIS при локальной сборке Windows;
- Windows x64 для получения Windows-установщика.

### Запуск в режиме разработки

```bash
npm ci
npm run tauri dev
```

### Проверки и сборка frontend

```bash
npm run typecheck
npm test
npm run build
```

### Сборка Windows-установщика

В среде Windows с установленными зависимостями:

```bash
npm ci
npm run tauri build -- --bundles nsis
```

Если команда Tauri в вашей версии CLI не принимает аргумент в таком виде, используйте эквивалентную команду CLI `npx tauri build --bundles nsis`. CI workflow — основной воспроизводимый сценарий сборки в этом репозитории.

## Автоматическая сборка и релизы

Workflow: `.github/workflows/build-windows.yml`

- запускается при push в `main`, pull request в `main) и вручную через GitHub Actions;
- при push тега вида `v*` собирает Windows NSIS installer;
- при успешной сборке тега публикует GitHub Release и прикладывает установщик.

После принятия изменений в `main` релиз создаётся тегом, например `v3.0.0). Не переиспользуйте уже опубликованный тег для другой сборки.

## Лицензия

В репозитории пока не указан файл лицензии. До выбора и добавления лицензии не следует предполагать, что сторонние пользователи имеют право распространять или изменять код. Перед публичным релизом выберите лицензию, соответствующую намерениям автора, и добавьте её в корень репозитория.
